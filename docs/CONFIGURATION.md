# Справочник конфигурации

> Документация для версии **roamd 1.3.6-r1** (веб-интерфейс **luci-app-roamd 1.3.6-r1**).
>
> Проект передан [freenetic](https://github.com/unisequence/freenetic) — дальнейшее
> развитие идёт в его рамках.

Все настройки `roamd` хранятся в `/etc/config/roamd`. После ручной правки примените их:

```sh
uci commit roamd
/etc/init.d/roamd reload
```

`reload` перечитывает конфигурацию без перезапуска процесса и без разрыва соединений. На
контроллере Mesh Wi-Fi-системы изменение `roamd` и `wireless` раскатывается на узлы
автоматически (см. [MESH.md](MESH.md)).

Отсутствующая опция принимает значение по умолчанию. LuCI не хранит значения, равные
умолчанию, поэтому действующий набор удобнее смотреть так:

```sh
ubus call roamd config
```

Логические опции принимают `1`, `true`, `yes`, `on` как «включено», остальное — «выключено».

## Секция `roamd 'global'` — механизмы роуминга

| Опция | По умолчанию | Смысл |
|---|---|---|
| `enabled` | `1` | Главный выключатель. При `0` демон завершается сразу после запуска |
| `band_steering` | `1` | Активное управление диапазоном: отказы в непредпочитаемом диапазоне и перевод |
| `prefer_band` | `5` | Предпочитаемый диапазон: `5` (или `high`), `2.4` (`2`, `low`); другое значение отключает предпочтение |
| `fast_transition` | `1` | 802.11r для сетей WPA2/WPA3 |
| `ft_over_ds` | `0` | 802.11r через распределительную систему. Многие iPhone и Android-телефоны работают с ним хуже, чем с FT по воздуху; при обновлении значение `1` один раз сбрасывается в `0` |
| `mobility_domain` | пусто | Четыре hex-цифры; пусто — вычислить из SSID |
| `neighbor_reports` | `1` | 802.11k: Neighbor Report и Beacon Report |
| `bss_transition` | `1` | 802.11v: запросы на переход |
| `apply_wireless` | `1` | Прописывать параметры 802.11k/v/r в `/etc/config/wireless` автоматически |
| `max_inactivity` | пусто | Секунды (30–3600). Если задано и включено `apply_wireless`, пишется в `max_inactivity` каждой точки доступа (кроме транспортной `mesh_bh_*`): hostapd проверяет клиента, молчащего столько времени, и отключает его без ответа. Пусто — значение в `wireless` не трогается (у hostapd по умолчанию 300 с). Рекомендуется `90`. Первое применение перезапускает Wi-Fi |

## Секция `policy 'policy'` — пороги и тайминги

Уровни — в дБм, разницы — в дБ, времена — в миллисекундах.

| Опция | По умолчанию | Смысл |
|---|---|---|
| `rssi_good` | `-55` | Хороший сигнал в предпочитаемом диапазоне: выше — клиента уводят туда |
| `rssi_low` | `-75` | Слабый сигнал: ниже — в предпочитаемый диапазон не уводят, а в нём самом клиент становится кандидатом на уход |
| `rssi_diff` | `30` | «Разница между диапазонами»: клиента не уводят с текущего диапазона, если тот сильнее целевого на эту величину, и уводят, если целевой сильнее на эту величину. Сравниваются только измеренные уровни: без измерения второго диапазона клиента не трогают |
| `node_rssi_diff` | `12` | «Разница между устройствами» Mesh Wi-Fi-системы: клиента переводят на другое устройство, если оно слышит его на столько дБ лучше **в том же диапазоне**. Устройство без этого диапазона и устройства, запрещённые клиенту, в выборе не участвуют |
| `steer_rssi` | `-73` | «Просить уйти ниже»: в Mesh Wi-Fi-системе клиента слабее этого уровня просят перейти (802.11v) и дают короткий список точек системы — до 3, 5 ГГц выше 2,4 ГГц, затем по тому, как точки его слышали. Точку выбирает сам клиент. После отказа просят снова, только когда сигнал упадёт ещё на 5 дБ |
| `steer_rssi_max` | `-65` | «Не трогать выше»: в Mesh Wi-Fi-системе клиента сильнее этого уровня не переводят никогда. Между порогами работают только поправки: после `hold_time` один запрос с одной целью, если клиент измерил явно лучшую точку (не чаще раза в 10 минут и не назад, откуда ушёл), и перевод по пробам, если другое устройство слышит клиента на `node_rssi_diff` лучше (не чаще раза в 5 минут) |
| `kick_rssi` | `-82` | Ниже этого уровня клиента уводят с диапазона в любом случае |
| `deny_probe` | `1` | Не отвечать клиенту в непредпочитаемом диапазоне; `0` — только запросы 802.11v |
| `steer_deny` | `0` | 15 с после запроса на переход точки, которых не было в списке, не отвечают клиенту; после 3 попыток его пускают |
| `beacon_once` | `0` | Клиенту между `steer_rssi` и `steer_rssi_max`, который 10 минут не сканировал эфир, отправляется один Beacon Request, не чаще раза в 15 минут |
| `allow_kick` | `0` | Отключать клиентов без 802.11v, которых нужно перевести |
| `hold_time` | `30000` | Сколько клиента не трогают после подключения |
| `steer_retries` | `3` | Запросов на переход за одно подключение (с паузой не меньше 5 с) |
| `deny_time` | `15000` | Сколько подряд отказывать клиенту, прежде чем сдаться; срок запрета возврата после принудительного отключения |
| `check_time_high` | `4000` | Срок годности наблюдения клиента в 5 ГГц |
| `check_time_low` | `8000` | Срок годности наблюдения клиента в 2,4 ГГц |
| `age_time` | `90000` | Сколько помнить клиента; на столько же клиент пропускается после «сдаться» |
| `poll_interval` | `2000` | Период опроса hostapd |
| `beacon_req_interval` | `20000` | Минимальный интервал между Beacon Request одному клиенту |
| `beacon_poll_interval` | `0` | Как часто спрашивать клиента с 802.11k о сигнале точек других устройств (по одной точке за запрос, по кругу, все диапазоны). По этим замерам контроллер выбирает лучшую точку в системе, в том числе в другом диапазоне; 2,4 ГГц должен выигрывать у 5 ГГц на `rssi_diff`. `0` — выключено |
| `log_level` | `1` | `0` — ошибки, `1` — обычный, `2` — отладочный |

Демон исправляет несовместимые значения при загрузке:

| Условие | Исправление |
|---|---|
| `rssi_good` не выше `rssi_low` | `rssi_good = rssi_low + 10` |
| `rssi_diff` меньше 1 | `1` |
| `node_rssi_diff` меньше 1 | `1` |
| `steer_rssi_max` ниже `steer_rssi` | `steer_rssi_max = steer_rssi` |
| `poll_interval` меньше 500 | `500` |
| `age_time` меньше `hold_time` | `age_time = hold_time × 3` |
| `steer_retries` равен 0 | `1` |

## Секции `wifinet` — беспроводные сети

Одна секция на сеть (имя `roamd_net_<id>`, где `<id>` — короткий хеш имени сети). Секция
появляется, когда роуминг у сети выключают в веб-интерфейсе; для сетей без секции роуминг
включён.

| Опция | По умолчанию | Смысл |
|---|---|---|
| `ssid` | — | Имя сети, к которой относится правило |
| `roaming` | `1` | Помогать клиентам этой сети переходить между точками и устройствами. При `0` у точек сети не включаются 802.11r/k/v, её клиентов не переводят ни между диапазонами, ни между узлами |
| `vid` | — | Метка VLAN сети-сегмента (3..15). Выбирается контроллером при появлении сети на отдельном интерфейсе; менять не нужно |

На узле такие же секции приходят от контроллера вместе с профилем — править их на узле
бессмысленно.

## Секции `device` — правила для клиентов

По одной анонимной секции на клиента.

| Опция | Смысл |
|---|---|
| `mac` | MAC-адрес клиента в нижнем регистре |
| `band` | Разрешённый диапазон: `2.4` (`2`, `low`) или `5` (`high`); нет опции — оба |
| `node` | uci-**list** разрешённых устройств Mesh Wi-Fi-системы: `controller` или `member_id` узла; нет опции — все |
| `alias` | Имя клиента для интерфейса; на поведение не влияет и на узлы не раскатывается |

Секция без `band` и `node` на политику не влияет.

Правила действуют одинаково на всех устройствах Mesh Wi-Fi-системы и проверяются на каждом шаге
подключения — запрос, аутентификация, ассоциация, — а также у уже подключённых клиентов. Клиента,
оказавшегося на запрещённом диапазоне или устройстве, отключают сразу; такое отключение не
считается попыткой перевода и пишется в журнал событием «устройство не разрешено» или «диапазон не
разрешён». Если разрешённого диапазона нет ни на одном устройстве системы, правило `band` не
применяется нигде, а карточка клиента показывает «Правило не действует: в Wi-Fi-системе нет точек
этого диапазона» — иначе клиент остался бы без сети.

```sh
d=$(uci add roamd device)
uci set roamd.$d.mac='aa:bb:cc:dd:ee:ff'
uci set roamd.$d.band='2.4'
uci add_list roamd.$d.node='controller'
uci add_list roamd.$d.node='a1b2c3'
uci commit roamd
/etc/init.d/roamd reload
```

То же делает метод `mesh_client_update` и карточка клиента в LuCI.

## Секция `mesh 'mesh'` — Mesh Wi-Fi-система

### Общие

| Опция | По умолчанию | Смысл |
|---|---|---|
| `enabled` | `1` | Включить mesh-часть демона; при `0` устройство работает как одиночный роутер без MESH |
| `role` | `controller` | `controller` или `node`. Узлом устройство делает захват; менять вручную не нужно |

### Контроллер

| Опция | По умолчанию | Смысл |
|---|---|---|
| `controller_id` | генерируется | 16 hex-символов; создаётся при первом старте контроллера |
| `controller_name` | пусто | Имя контроллера для отображения |
| `backhaul_enabled` | `1` | Вещать беспроводную транспортную сеть, когда в системе есть узлы |
| `backhaul_ssid` | генерируется | Имя транспортной сети, по умолчанию `Service-Mesh-<id>` |
| `backhaul_key` | генерируется | Ключ транспортной сети |
| `backhaul_delta` | `20` | На сколько дБ сигнал 5 ГГц может уступать 2,4 ГГц при выборе диапазона звена узла |
| `backhaul_min_signal` | `-78` | Нижняя граница рабочего звена узла: более слабое звено используется, только если сильнее ничего не слышно; слабее этого уровня 5 ГГц уступает 2,4 ГГц |
| `wifi_shutdown` | `0` | Гасить точки доступа узла, пока у него нет пути к контроллеру |
| `ft_key` | генерируется | 64 hex-символа: общий ключ обмена ключами 802.11r между точками в сетях WPA3 и WPA-Enterprise |
| `pkg_url` | пусто | Репозиторий пакетов для узлов и самообновления; пусто — репозиторий проекта. Только `https://`; `%b` — ветка, `%a` — архитектура, без подстановок — `<url>/<ветка>/<арх>`. Для своего репозитория его сертификат кладётся в `/etc/roamd/pkg.crt` |
| `auto_update` | `0` | Автоматическое обновление контроллера и узлов |
| `auto_update_every` | `1` | Период проверки: число |
| `auto_update_unit` | `day` | Период проверки: `hour` (до 23), `day` (до 31), `week` (до 5), `month` (до 12) |
| `auto_update_last` | — | Unix-время последней проверки; пишет автообновление |
| `auto_update_result` | — | Итог последней проверки: `updated`, `none`, `error` |
| `txpower_24`, `txpower_5` | пусто | Мощность передатчика (дБм) радио контроллера по диапазонам; пусто или `0` — не трогать, снимается только записанное roamd значение |
| `channel_24`, `channel_5` | пусто | Канал радио контроллера. 2,4 ГГц: 1–13; 5 ГГц: 36–48 и 149–177 (DFS-каналы не предлагаются). Пусто — канал roamd не управляет; снятие записанного значения возвращает `auto` |
| `width_24`, `width_5` | пусто | Ширина канала (МГц): 2,4 ГГц — 20/40, 5 ГГц — 20/40/80/160. Стандарт (HT/VHT/HE/EHT) берётся из текущего `htmode`; при очистке `htmode` остаётся прежним |
| `country` | пусто | Регуляторный регион (`XX` или `00`) для контроллера и всех узлов (LuCI: MESH → Настройки → Радио). Пусто — узлы получают регион радио контроллера (`wireless.<радио>.country`), сам контроллер не меняется. Сначала переключаются узлы, контроллер — после их ответа |

Выбор региона, каналов и мощности — ответственность владельца: roamd только записывает значения
в `/etc/config/wireless`, соблюдение местных правил использования радиочастот остаётся за
пользователем.

### Узел

Пишутся при захвате и из профиля контроллера; в LuCI узла доступны только для чтения.

| Опция | Смысл |
|---|---|
| `controller_id` | Идентификатор контроллера, чей профиль принимается |
| `controller_name` | Имя контроллера для баннера |
| `controller_addr` | Адрес контроллера; он же DNS-forwarder узла |
| `member_id` | Идентификатор узла — последние 6 hex-цифр MAC |
| `backhaul_parents` | Транспортные точки системы для выбора родителя: записи `<bssid>/<глубина>/<цепочка>/<диапазон>` через пробел |

Узел также получает из профиля `backhaul_*`, `wifi_shutdown`, `ft_key`, `country` и свои
`txpower_*`, `channel_*`, `width_*` (в `roamd.mesh` они хранят то, что roamd записал в
`wireless`, чтобы позже снять). Канал диапазона, по которому идёт беспроводная транспортная
сеть узла, профиль не меняет: он задаётся родителем.

## Секции `member` — узлы (только контроллер)

По одной на узел; создаются захватом.

| Опция | Смысл |
|---|---|
| `id` | `member_id` узла |
| `name` | Имя для отображения; по умолчанию — hostname устройства, у заводского `OpenWrt` — модель, при совпадении с именем другого узла дополняется `member_id`. Повторный захват имя не затирает. Пока имя совпадает с прежним `hostname` (или `<hostname> <id>`), оно меняется вслед за переименованием узла; имя, заданное в LuCI, сохраняется |
| `hostname` | Системное имя устройства; обновляется по отчёту узла при каждом опросе |
| `mac` | MAC аплинка узла |
| `addr` | Адрес узла, закреплённый за ним при захвате |
| `managed` | `1` — узел получает профиль; `0` — только опрашивается |
| `bh_node` | Список узлов, через которые разрешён беспроводной путь (раздел 13 MESH.md) |
| `txpower_24`, `txpower_5`, `channel_24`, `channel_5`, `width_24`, `width_5` | Радио узла по диапазонам, значения и правила — как у контроллера; передаются в блоке `txpower` профиля |

Секреты в UCI не хранятся: сертификат узла — в `/etc/roamd/members/<id>.crt`, токен входа —
в `/etc/roamd/tokens/<id>` с правами `0600`.

## Что пишется в чужие конфигурации

| Файл | Кто и что пишет |
|---|---|
| `/etc/config/wireless` | автонастройка: опции 802.11k/v/r точек доступа; контроллер и узлы: транспортные точки `mesh_bh_<радио>`, а по настройкам радио — `txpower`, `channel`, `htmode`, `country` на `wifi-device`; узел: станция `mesh_bh_sta` с BSSID родителя, SSID/шифрование/ключ из профиля, `disabled` при `wifi_shutdown` |
| `/etc/config/network` | контроллер с узлами: `stp=1` и `priority=4096` на мостах; узел при захвате: мост с `stp=1`, статический `lan` с закреплённым адресом, шлюзом и DNS контроллера, удаление `wan`/`wan6` |
| `/etc/config/dhcp` | контроллер: резерв адреса узла `roamd_<member_id>` (`host`), снимается при удалении узла; узел: выключенный DHCP-сервер, forwarder на контроллер |
| `/etc/config/firewall` | узел при захвате: удаление зоны `wan`, `forwarding` и секций `nat`, снятие `masq`/`masq6` в остальных зонах |
| `/etc/config/system` | узел: `timezone`, `zonename` из профиля |
| `/etc/config/uhttpd`, `/etc/config/rpcd`, `/etc/config/dropbear` | узел при захвате: сертификат, вход `mesh-<id>`, запрет парольного SSH |
| `/etc/shadow` | узел: хеш пароля `root` из профиля |
